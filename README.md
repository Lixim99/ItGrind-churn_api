🎯 Конкретная задача классификации
Клиент может уйти из сервиса в следующем месяце или остаться. Целевая переменная churn принимает значение 1 если клиент ушёл, 0 если остался.

📊 Признаки в датасете
1. 💰 monthly_fee — ежемесячная стоимость тарифа клиента
2. ⏰ usage_hours — количество часов использования сервиса за последний месяц
3. 🎧 support_requests — количество обращений в техподдержку
4. 📅 account_age_months — возраст аккаунта в месяцах
5. ❌ failed_payments — количество неудачных платежей
6. 🌍 region — регион клиента (europe, asia, america, africa)
7. 💻 device_type — основной тип устройства (mobile, desktop, tablet)
8. 💳 payment_method — способ оплаты (card, paypal, crypto)
9. 🔄 autopay_enabled — включено ли автосписание (0 или 1)
10. 🎯 churn — целевой признак (1 клиент ушёл, 0 клиент остался)

Тесты запускаются из корня проекта:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

Unit-тесты подготовки данных, обучения и сохранения модели без FastAPI:

```bash
python -m pytest tests/test_dataset.py tests/test_preprocessing.py tests/test_model.py
```

Интеграционные тесты через `TestClient`:

```bash
python -m pytest tests/test_churn_flow.py
```

Тесты используют 40 синтетических строк с равным числом классов и фиксированный
`random_state=42`. CSV `data/churn_dataset.csv`, модель и история обучения создаются
в отдельном временном каталоге каждого теста. Рабочие данные проекта не изменяются.
Полный API-сценарий проверяется для логистической регрессии и случайного леса:
чтение CSV через `/dataset/preview`, обучение, статус, пакетное предсказание и история
метрик. Проверяются также отсутствие обученной модели (404) и ошибки входных данных (422).
